# Self-Hosted LiveKit For GhostTalk

GhostTalk can use your own LiveKit deployment for embedded video rooms inside the app.

Required backend variables:

```text
LIVEKIT_URL=wss://livekit.example.com
LIVEKIT_API_KEY=your-api-key
LIVEKIT_API_SECRET=your-api-secret
```

GhostTalk keeps the same anonymous session model:

- no user registration
- no email binding
- room name generated from the GhostTalk session code
- short-lived access tokens generated by the backend

## Recommended topology

Use separate public endpoints:

- `https://ghost-talk.online` for GhostTalk
- `wss://meet.ghost-talk.online` for LiveKit

This keeps the application and media server isolated.

## Official LiveKit sources

- `https://docs.livekit.io/home/self-hosting/deployment/`

## Connect GhostTalk to LiveKit

Set these values in the GhostTalk backend environment and redeploy:

```text
LIVEKIT_URL=wss://livekit.example.com
LIVEKIT_API_KEY=devkey
LIVEKIT_API_SECRET=replace-with-strong-secret
```

## Notes

- `LIVEKIT_URL` should be the public websocket endpoint reachable by the browser.
- API key and secret stay only on the backend.
- If you want stricter moderation, lobby, egress, SIP, or advanced policies, configure them on the LiveKit side.
